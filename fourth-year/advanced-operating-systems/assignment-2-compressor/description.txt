The hardest part of the assignment for me was correctly adding and setting up the bpf functions and the system calls, as well as making sure that the new bpf program type can be verified and passed through the system calls. This was mostly done through looking at the implementation of other bpf programs & trial + error.
One thing to mention is that i made an unfortunate decision at the beginning to change the BPF_TRAMP type to BPF_TRAMP_MODIFY_RETURN, instead of BPF_TRAMP_REPLACE (in order to avoid the problem mentioned in the hints). Then i spent a lot of time debugging why the bpf program was not getting the right arguments. It turned out that simply fixing the assumption from the mentioned patch that the tgt_prog was not null was much easier. I've added a few if statements to account for that case. 
As to how the buffer is passed within the program: I simply create a larger ctx that contains it and only pass it's field to the bpf program. This means that within the helper functions I can still access the larger structure.

Notes:
As mentioned in the patch, I assume that the lzo_compress function is supposed to move the compressed data to the internal buffer.
I stole a nice idea to use the COMPRESSOR_HOOK (which i think is quite elegant) from the implementation of another bpf program, LSM.
The solution calls the compressor_verify program after the write has occurred. It seems to me that in vfs_writev, the writes from all buffers are treated as a single operation, using the filp->write_iter  function. This means there isn't an easy way to call the compressor between the separate writes (since we should treat each buffer separately). So I've decided that the compressor should be called after the original write operation has finished, so the iov iterator is used to go over the buffers again, calling the compressor verify.
